# 背景采集与材料解释

## 足够开始的信息

从用户描述、表单和聊天截图提取已有信息，不让客户重复填写。缺项写“未提供”。先补最影响选校的少数问题，同时推进不依赖答案的检索。

| 项目 | 需要保留的区分 |
|---|---|
| 学位目标与时间 | 本科／硕士／博士／其他资格；授课型／研究型／专业学位；具体入学年和学期 |
| 已有与在读学历 | 本科申请看高中课程体系与考试；研究生申请看全部相关高等学历。记录学校、专业、学位类别、毕业或预计毕业时间及授予状态 |
| 第二学历 | 第二学士／双学位／辅修的实际性质、学校、状态、已修课程、预计完成时间。不要仅凭“读软件工程”推定已取得工学学位 |
| 学术成绩 | 加权均分、算术均分、GPA、满分制、排名、学校官方换算规则分别记录 |
| 关键课程 | 按目标学科提取课程、学分、分数和内容。可能是研究方法、经济学、文学写作、教育学、设计工作室、数学、实验或临床训练；不默认要求编程 |
| 语言 | 考试类型、总分、单项、日期、考试形式；有效期按项目规定的参照时间核查 |
| 经历与专项材料 | 按领域看研究、写作样本、作品集、试演、教学／行业／临床经历、资格证、论文与竞赛。核实本人贡献、时长和成果，不将各类经历互相等价 |
| 目标 | 希望学习的具体内容、目标岗位／研究主题、就业地区、是否需要执业资格，学术／职业／创作偏好 |
| 路径接受度 | 同专业、相邻专业、转专业、交叉学科、转换课程或桥梁课程；可接受的补课成本及学习强度 |
| 专项考试 | 仅在目标项目要求时核GRE／GMAT、入学考试、学科考试、作品评审或面试；不默认所有学科都需要 |
| 范围与预算 | 允许／排除的地区、学校实体与校区；自主申请／统考／推免等渠道；全日制要求、可接受学制、币种、总预算是否含生活费、弹性。预算未定不等于无限预算 |
| 交付 | 详细报告／简表／CSV，是否保留来源和分级，是否需要人工审核 |

## 冲突和缺失的处理

- 若表单写“本科在读”，聊天写“第一本科毕业、第二学士在读”，分别保留两段学历，标注时间线待确认，不自行合并。
- 同时给出加权 79.6 和算术 80.28 时，不挑高分使用或把 79.6 四舍五入成 80。按申请表指定口径填报；未明确时两者并列，不臆造 GPA。
- 不将百分制直接等同于“平均 B 等”或某个荣誉等级，除非有学校认可的规则。
- 只有雅思总分时，可核对总分门槛，但不能宣称语言要求全部满足。
- 计划中的第二学位、实习或语言成绩不冒充已取得成果。若官网允许应届申请或入学前补交资格，按实际提交与补交时点核验，标“按期毕业／补交为前提”，不误判所有在读生不符合；未核准这一路径前不自行假设允许。
- “可以盖章”不等于已完成实习；大创结项不等于获奖或论文。记录实际职责、贡献和可提供的证明。
- 判断必须依赖缺失信息时，给出条件分支。例如“若第一学位属理工，可走路径 A；否则须核工作经历路径 B”。不要因信息缺失让全部检索停住。

## 客户隔离

案例可用 `case-001` 等匿名代号组织。新客户开始时重新建立背景表；以前的学校入口可复用，个人数据及分级不可复用。例子仅用于解释规则，不作为任何新客户的默认背景。
